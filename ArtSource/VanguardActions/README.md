# Swordguard complete rig / authored local motion layer

The default combat presentation uses the existing articulated body plus Blender ActorModules. Equipment, upgrades, fashions and tactics remain separate objects on that rig. The imported five-clip whole-body pilot is a bounded preview; it is not a complete combat replacement.

This E01 addition supplies 13 original Blender-baked additive pose channels, sampled on the actual existing rigid joints: idle; forward/back/left/right gait; left/right turning; basic; first active; jump; landing; hit; death terminal pose. It **enhances the existing complete actions**, not 13 newly authored full-skeleton animations. Later active skills and charge keep their existing complete poses. No hitbox, displacement, damage, action duration, contact time or control time is changed. Accepted gait phase, local velocity, turn load, jump tuck, landing impulse and existing action progress remain authoritative. Hit is a short additive recoil, never an action cancellation. Death's existing root fall remains PlayerController-owned; local joints apply a static authored terminal pose even when the death screen freezes scaled time; this is not a continuous animation during pause.

`CombatModel.VanguardArt` selects the complete binary library once when building the character. Unsupported classes, missing joints, disabled authored modules, missing or invalid binary choose the complete existing motion path. Equipment replacement never changes that decision or swaps the character body. The partial applies before existing visual recovery so recovery retains final priority.

Original source: `build.py` key poses, no external asset/license/purchase. `Swordguard-Actions.blend` retains individually named editable actions with fake users. Bake with Blender 4.3.2 (or export hand-edited named actions from the saved .blend with `export_blend.py`):

```
blender -b --python ArtSource/VanguardActions/build.py
python3 Tests/VanguardActionsProductionTests.py /path/to/dotnet
python3 ArtSource/VanguardActions/export_actions.py /tmp/vanguard-actions /path/to/dotnet
blender -b --python ArtSource/VanguardActions/render.py -- /tmp/vanguard-actions/actions.json
```

Budget: one 46,348-byte binary (13 × 33 × 9 Vector3 plus header), zero new triangles/materials/textures/renderers, no runtime curve parsing or per-frame allocation. Sampling performs bounded local rotation additions. Decoder rejects truncated/oversized/schema-mismatched/nonfinite/out-of-budget data as a whole. Stable meta GUIDs are checked in. Source animations use linear interpolation; runtime resamples linearly.

Evidence: `managed-production.log` executes the actual binary decoder and actual CombatModel adapter with managed transform doubles (15,135 assertions). It covers every routed pose, stable body/joint identity, finite interpolation, missing-library fallback and dead-owner priority. Existing equipment composition tests retain their separate actual construction scope. `Factory-Additive-Poses.png` uses actual production factory geometry/hierarchy and actual baked offsets **on the construction rest pose**, rendered by Blender; it does not represent the full runtime blended locomotion/action, imported Unity animation, GPU skinning, or a device capture.
