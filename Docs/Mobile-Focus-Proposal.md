# 手机固定目标：设计与验收提案（未实现）

本项只定义下一轮可评审方案。默认触控、自动选敌、相机、技能扣费与蓄力行为全部保持现状；本文不代表已实现或已完成真机验收。不新增粒子、空间索引、技能或资源奖励。

## 已核对的生产入口

- `MobileControls.ProcessPointer` 先分配技能、摇杆、普攻、集火／召回、交互、闪避、药剂等角色；未被 UI 占用的世界触点才进入 `Role.Aim` 或 `Role.Camera`。`MobileCameraGesture.Begin/Move` 当前只接收 y，超过 9 个逻辑单位的纵向位移才判定相机拖动；纯横向拖动没有对应的“非点击”判定。现阶段世界轻触没有固定目标功能，因此这不是已发生的误选敌结论，而是加入点选前必须解决的冲突。
- `PlayerController.ResolveMobileAim` 每帧按移动方向／朝向，在 14 米、左右各 75°、直线可见的敌人中取最近者。`PrepareMobileSkillAim` 是另一入口：按技能范围与直线可见性筛选，`AimTarget` 或 `FocusTarget` 都被放进同一个优先候选类别，不能直接等同于新的“玩家手动锁定优先级”。
- 现有 `FocusTarget` 是召唤师普攻真实命中后产生的限时职业集火，受存活、距离和时间约束；`SummonedCompanion.ExplicitFocus` 是独立的团队免费命令。不得把这两种状态改名冒充手机手动固定目标，也不得让点选偷偷发出宠物指令、刷新职业集火时间或改变共鸣触发条件。
- `SkillTargetingController.Begin` 在移动端先 `PrepareMobileSkillAim`，需要地面确认的技能也直接调用 `ConfirmTargetedSkill`；当前手机不是统一的“点技能后再点地面”操作。`ConfirmTargetedSkill` 把落点交给视线裁剪，通常清除敌人引用，仅特定召唤契约保留符合条件的敌人身份。
- `SkillChargeController.Begin` 一次记录 `TargetPoint/TargetEnemy/Direction`；普通召唤契约默认优先团队显式目标。释放前检查敌人存活、列表归属、距离与视线，失效时清敌人引用，不把已记录落点换成另一敌人。`ExecuteChargedSkill` 使用记录的落点与方向，不能从当帧自动目标重新选址。
- `CombatTargetFeedback` 已有自动瞄准括角、集火菱形和已锁蓄力落点三种常驻标记；新设计应在这套有界显示中扩展语义，不叠一套持续生成的特效。

## 拟议操作与手势边界

1. 仅在正常冒险、玩家存活、没有输入阻止或过渡门禁、没有主动地面放置时，世界触点可成为“点选候选”。开始于 UI、十格技能、摇杆、按钮、通知、地图或安全区之外的触点，不可在滑出这些区域后变成点选。
2. 记录同一指针的起点、角色／战斗 epoch、视口版本。用 `(dx²+dy²)/Scale² >= 9²` 将候选永久判为拖动；暂以现有 9 逻辑单位作为可测起点，真机验收前不宣称阈值合适。相机仍只使用纵向增量调俯仰；纯横向跨阈值也要取消点选，但不凭空引入水平旋转。跨阈值后回到原点，释放仍不是点击。
3. 只有同一指针正常释放、全程未被取消且释放仍处于可交互世界区域，才尝试命中敌人。沿用已有投影包围盒／近裁面排除与遮挡规则；开始与释放都须指向同一有效敌人，重叠时使用稳定的屏幕距离、深度及列表顺序裁决。空白轻触清除手动固定目标，不施法、不移动角色。
4. 一次最多一个世界候选。左拇指已经持有摇杆时，右指可点敌；第三指、非所有者释放不能替换或提交候选。技能／其他控制触点与候选并存时，以控制动作优先：取消候选，不让控制释放顺带换目标。继续使用原有 initiating-pointer 过渡抑制，不把普通前台交互扩大为全触点释放要求。
5. Canceled、触点消失、失焦／后台、安全区／旋转／DPI变化、打开面板、暂停、返回、角色死亡或换房均丢弃未完成候选；恢复后必须新按下才可点选。系统返回维持现有 modal→页面层级→蓄力／瞄准取消→暂停的规则，不插入“先解锁敌人”一级。

## 拟议目标规则：单独保存手动意图，共用执行入口

拟新增仅本次战斗的手动目标引用与 epoch，不写入存档，不借用 `focusedEnemy/focusTime`。有效手动目标在普攻移动瞄准和技能准备两个入口中都优先于普通自动候选；无手动目标时完整回退原自动行为。自范围技能仍以玩家为中心，不清除另行保存的手动意图。

| 情况 | 普通操作意图 | 已开始蓄力 |
| --- | --- | --- |
| 轻触有效敌人 A | 后续普攻和适用技能优先 A；不扣费、不发宠物命令 | 本次记录的落点／方向不变；新意图只用于下一次操作 |
| 改选 B 或轻触空白 | 更新／解除手动意图 | 不重定向当前蓄力、不重启计时 |
| A 死亡、移出敌人列表、超过普通 14 米有效距离 | 清除手动意图，下一次正常操作回到自动选择 | 保留原地面快照；按原释放验证清除失效敌人引用 |
| A 被墙遮挡 | 保留意图，显示“遮挡”；需要直线目标的操作不得暗换另一敌人，不扣失败费用 | 按现有快照与释放视线规则执行，不追踪穿墙目标 |
| A 在普通范围内、但超出所点技能范围 | 保留意图并给“距离不足”短反馈；该次目标依赖技能不暗换目标、不扣费 | 已锁快照不受新技能尝试影响 |
| 死亡、换房、换角色 | 清除手动意图、候选与标记 | 沿既有 epoch／取消路径清理，不把旧落点带进新房 |
| 暂停、打开面板、后台 | 取消候选并隐藏战斗标记；保留手动意图仅限同玩家同 epoch，恢复前重新验证 | 保持现有暂停／取消政策，不借恢复流程重选落点 |

契约技能是明确的既有例外：普通契约继续遵循团队显式命令，主动指定只临时覆盖对应伙伴，结束恢复最新团队命令。手机点敌本身不算“免费集火”或“主动契约指定”。若当前契约会以团队目标 C 开始，预览／锁点标记必须显示 C，不能画手动 A 却施放 C。自范围／方向／地面技能分别遵守自身形状和裁剪规则；不把所有技能强行改成锁敌技能。实施前需把这些分支接到真实 `Begin→ConfirmTargetedSkill→charge.Begin→ExecuteChargedSkill` 路径，而不只修改候选 helper。

## 可辨认反馈

手动目标拟使用固定双角框，自动目标沿用单括角，团队集火沿用菱形，蓄力锁点沿用地面锁点形状；颜色作为辅助而非唯一差别。相同对象上的标记应合并布局，避免多个圈覆盖脚下。新标记使用复用的有界几何，不新增粒子或逐点击生成对象。

目标旁最多一条真实相关状态：优先“遮挡／距离不足”，否则显示该目标已有的职业相关状态（如霜痕、灼烧、毒层）；没有真实状态就不造“易伤／可爆发”标签。蓄力时锁点标明“本次已锁”，若普通手动意图已换目标，最多补“下次”短标识，避免把下一次目标误认为本次落点。不可用血量加成、伤害数值或新增战斗日志伪装视觉反馈。

## 可托管验证：实施后必须通过

- 对实际手势分类与 `ProcessPointer` 接线重放：阈值内点击、横／纵／斜向越界、越界后回原点、Canceled、触点丢失、UI内开始／世界外释放、摇杆11→候选12→控制13、多指非owner释放。变更 Scale／安全区后旧指不得提交。旧 y-only 分类的负对照必须在纯横拖不点选断言失败。
- 对真实普攻瞄准与 `PrepareMobileSkillAim` 两入口验证同一有效手动 A 优先于更近 B；无手动状态时旧自动排序保持。覆盖自范围、短距离技能拒绝、遮挡、不在列表、死亡、超距与同名新敌人，测试不得通过复制一份选敌算法代替生产调用。
- 对真实 targeting／charge 路径验证：A开始→改选B→释放仍用原快照；A死亡／超距→清引用但原地面点不偷换；换房／角色→取消；重复点选不改能量、CD、伤害、宠物寿命或攻击计时。召唤团队C与普通手动A同时存在时，契约实际目标、预览和锁点一致。
- 对真实生命周期与返回顺序验证：UI先跑／Player先跑均不串用同帧Back；原手动暂停不会因恢复前台解开；前台单指过渡与后台全指门禁保持原边界。固定目标不影响现有装备详情、技能详情、宝箱暂停返回回归。
- 以可记录的 owner/epoch、目标引用、点与资源快照断言标记读数；关闭／销毁清理、并发上限可做托管契约。此类测试只能证明状态与接线，不能证明图标在屏幕上易认、响应顺滑或性能达标。

## 必须 Unity／真机验收

用 Unity 6000.6.3 对共享三端运行时做精确 API 编译，再用实际 Android/iPhone/iPad 检查：568×320逻辑布局与不同DPI安全区；左右手持杆点敌；密集重叠敌人与前景遮挡；横向擦动不误锁、斜向调镜头；三指、系统手势边缘、旋转、后台恢复和 Android 系统返回接线；蓄力中换目标时“本次／下次”是否可辨。需观察帧时间、分配与绘制实际数据后再给性能结论。编辑器鼠标模拟或托管回放不能替代上述设备验收。

放行前保持默认控制不变。若手势误判或标记不能清楚表达不同意图，应保留现有自动选择，不通过扩大点击区域、取消遮挡判断或增加粒子掩盖问题。
